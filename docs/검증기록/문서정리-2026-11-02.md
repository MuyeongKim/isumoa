## 링크·설명서·배포 입력 검사 방법

`check-doc-links.ts`는 Git 추적 파일과 새 비무시 Markdown을 검사한다. Markdown 참조·이미지·HTML의 `href`/`src`, 한글·공백·인코딩·fragment를 처리한다. 코드 예제·주석·외부 URL·앵커는 제외하며 네트워크 요청을 하지 않는다. 깨진 경로와 저장소 밖 대상은 오류로 보고한다.

설명서 테스트는 실제 문서를 렌더링하여 기본 주소와 `/kmy/edu-cert/` 하위 경로에서 그림 13개가 기존 주소를 사용하고 크기와 파일이 유효한지 확인한다. 빌드 뒤 `web/dist/manual.html`과 실제 그림 파일도 대조한다.

EXE를 만들지 않고 `release.ts`에서 네 문서 입력 참조를 추출해 UTF-8로 읽었다. 입력은 `사용자/PC설치안내.md`, `관리자/설치가이드.md`, `관리자/운영가이드.md`, `관리자/IT-확인요청서.md`다. 출력 파일 이름 `PC설치안내.txt`, `설치가이드.md`, `운영가이드.md`, `IT-확인요청서.md`는 유지했다. `release.ts`의 실행·복사·압축 진입점은 호출하지 않았다.

## 공고 원문과 구성 순서

[행정안전부 참가 안내](https://www.mois.go.kr/frt/bbs/type013/commonSelectBoardArticle.do?bbsId=BBSMSTR_000000000006&nttId=130237)의 README 요구는 접속 주소, 주요 기능, 실행·작동 방법 기재이며 전체 섹션 순서를 고정하지 않는다. 따라서 요청한 B-2 순서를 유지할 수 있다.

별도 PDF 양식 2-1은 실행 환경 → 설치·실행 → LLM 연결 → 모의데이터 → 기능 사용 순서 → 제약 → 개발 경위 순서다. README의 개발 경위를 앞에서 소개하는 것과 PDF의 양식 순서는 구분한다. 이 작업으로 최종 PDF나 참가 신청을 완료한 것으로 표시하지 않는다.

## 자리표시

README에는 다음 주석 세 개만 남긴다. 실측·Windows·SmartScreen의 본문은 추정해 작성하지 않는다.

```text
<!-- TODO(실측): 직원 N명, 엑셀 수기 대비 소요 시간 비교 결과 -->
<!-- TODO(Windows): Windows 10/11 실기기 설치·실행·Excel 열기 결과 -->
<!-- TODO(SmartScreen): 경고 화면 캡처와 "추가 정보 → 실행" 안내 -->
```

일반 제약은 README 9번에 모으되 요청한 TODO와 근처의 확인 전 한 줄은 3·6·9번의 명시적 예외로 둔다. SmartScreen의 실제 화면이나 실행 안내는 이 작업에서 새로 채우지 않는다.
