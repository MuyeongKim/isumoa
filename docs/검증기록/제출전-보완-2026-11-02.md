### 실제 구현과 맞춘 안내

- `deploy/windows-desktop/common.ps1`의 `$DataHome`은 `$env:LOCALAPPDATA` 아래 `isumoa`이다.
- 설정의 **백업·보관**에는 복원 버튼이 없다. 요청 문장 중 ‘백업·복원은 설정에서’는 ‘백업은 설정에서, 복원은 PC 설치 안내의 절차’로 구분했다. 해당 안내에는 복원 검사·적용 절차가 있다.
- `scripts/release.ts`는 `PC설치안내.txt`를 배포 ZIP 루트에 생성한다. EXE 설치 후 프로그램 폴더에 복사하는 파일은 아니므로 ‘설치 폴더’ 대신 ‘배포 ZIP을 푼 폴더’로 안내했다. EXE 설치법은 설명서 자체로 읽을 수 있게 했다.
- 추적된 스크립트에서 `demo-samples-*.zip`과 `모의자료_사용안내.md`의 생성 위치는 찾지 못했다. 새 생성 경로를 만들지 않았고 이미 게시된 ZIP은 수정하지 않았다.

## 검수 화면 변경

### 제외 확인창 쪽 번호

기존 `#11 · 스캔묶음_재무과.pdf` 표시를 **스캔묶음_재무과.pdf 1쪽**처럼 바꿨다. 이수증 아닌 쪽 일괄 제외와 일반 선택 제외 양쪽에 적용했다. 직원·과정·상태 안내는 유지했다.

`selection()`이 사용하는 `getCertificateRow()`는 이미 `pages.page_no`를 조회한다. 중복 조인 없이 `BulkExcludePreview.items.pageNo`로 전달한다. 미리보기와 적용은 계속 같은 `selection()`의 행·인정 연결·사용자·모드로 토큰을 계산한다. 확인창 이후 쪽 번호가 바뀌어도 이전 토큰은 거부한다.

### 빈 업로드 묶음: (가) 선택

이번 파일 선택에서 **새로 만든 묶음이며 완료 파일이 0개**일 때 화면이 `DELETE /api/batches/:id/empty`를 요청한다. 삭제가 확인돼야 현재 묶음 선택을 해제하고 목록을 다시 읽는다. 기존 묶음은 자동 정리 대상이 아니다.

서버는 인증과 생성자를 검사하며 관리자도 다른 사용자의 묶음을 지우지 못한다. `DELETE` 자체에 `NOT EXISTS(files)`를 넣어 파일이 하나라도 있으면 삭제하지 않는다. 원본만 저장되고 쪽 읽기에 실패한 묶음도 보존한다. 원본 수신 중인 묶음은 정리를 보류하고 모든 반환·실패 경로에서 수신 카운트를 해제한다. 실제 삭제에만 `batch.empty-delete` 감사 로그를 남긴다.

목록에서 숨기는 방식은 빈 기록을 계속 누적시키고, 재사용 방식은 연도·메모·동시 업로드의 의미를 섞을 수 있어 선택하지 않았다. 파일이 없는 새 묶음만 정리하는 방식으로 현재 선택과 기존 제출 자료를 구분한다.
