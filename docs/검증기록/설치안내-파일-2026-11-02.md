# EXE 설치 사용자에게 설치 안내 파일 제공

기준 커밋: `dc5b9bf` / 확인일: 2026-11-02 / 버전: 0.5.11 유지.

## 문제 재확인

기존 게시 ZIP의 최상위에는 `PC설치안내.txt`가 있지만 `program/PC설치안내.txt`와 해당 manifest 항목은 없었다. `windows-exe.ts`의 설치 EXE는 `program`과 `setup/install.ps1`만 포함하므로 EXE 설치 사용자가 설명서의 안내 파일을 찾을 수 없는 구조였다.

## 변경

| 위치 | 이전 | 이후 |
|---|---|---|
| `scripts/release.ts` | TXT를 ZIP 최상위에만 생성 | 같은 안내를 ZIP 최상위와 `program`에 모두 생성. 두 manifest 생성 경로보다 먼저 기록 |
| `install.ps1` | 실행·제거 바로가기만 생성 | 시작 메뉴의 `이수모아 설치 안내.lnk` 추가. 대상은 설치 폴더의 TXT, 인수는 빈 문자열 |
| 설치 실패 복구 | 기존 바로가기 3개 보존 | 안내 바로가기도 기존 바이트 또는 미존재 상태로 복원 |
| 업데이트 후 기동 실패 복구 | 새 안내 바로가기를 별도로 복구하지 않음 | 업데이트 전에 해당 바로가기만 보존하고 복구 시 그 상태를 되돌림 |
| 사용설명서 1-1 | ZIP을 푼 폴더의 안내만 설명 | 시작 메뉴 → 이수모아 → 이수모아 설치 안내. ZIP 최상위 TXT도 안내 |
| 사용설명서 문의 | ZIP 최상위 TXT의 7장 참조 | 시작 메뉴의 안내를 열고 ‘7. 문제가 생겼을 때’ 확인 |
| PC 설치 안내 | 프로그램·자료 폴더 설명 | 설치 폴더 안의 안내 TXT와 시작 메뉴 위치 한 줄 추가 |

설치 후 파일은 `%LOCALAPPDATA%\Programs\isumoa\PC설치안내.txt`이다. 바로가기는 PowerShell 실행용 함수를 재사용하지 않고 텍스트 파일을 직접 가리킨다. Windows 기본 텍스트 앱으로 열리며, 기본 파일 연결이 메모장이면 메모장으로 열린다.

## 설치·업데이트·제거 경로

- EXE 경로: 안내를 `program`에 기록 → `buildWindowsExe` → 실행기 컴파일 후 `writeProgramManifest` → 설치 EXE에 `program` 전체 포함. 안내 기록은 이 함수 호출 전이다.
- ZIP 경로: 같은 안내 기록 → `writeProgramManifest` → ZIP 생성. 기존 최상위 TXT는 유지한다.
- 설치는 `Invoke-ProgramUpdate`로 프로그램 폴더를 복사하고 manifest 크기·해시를 확인한 뒤 교체한다. 안내도 같은 검증·교체 대상이다.
- 자동 업데이트는 `apply-update.ps1`에서 새 설치 EXE를 `/S`로 실행하고, NSIS가 `setup/install.ps1 -FromExe`를 실행한다. 설치 후 `Register-Program`이 다시 호출되므로 안내가 없던 이전 버전 사용자도 새 파일과 바로가기를 받는다. 수동 EXE 덮어 설치도 같은 등록 경로다.
- 설치 실패 시 `UndoRegistration`이 안내 바로가기를 포함해 원래 등록을 복구한다. 새 바로가기는 제거하고 기존 바로가기는 원래 바이트로 돌린다.
- 보강된 업데이트 도우미는 설치 성공 후 새 앱 기동 검증에 실패할 때도 안내 바로가기만 복구한다. 다른 바로가기·설치 동작은 변경하지 않았다.
- `uninstall.ps1`은 시작 메뉴의 이수모아 폴더 전체를 제거하므로 새 바로가기도 함께 제거된다. 제거 코드는 수정하지 않았다.

## EXE 없이 실제 패키징 검증

원본 배포 폴더를 보존하고 분리된 작업 폴더에서 다음 명령을 실행했다.

```sh
npm run release -- --target win-x64 --desktop --download-node
```

`--exe`를 넣지 않았다. `makensis`를 호출하지 않았고 설치 EXE·실행기 EXE를 컴파일하지 않았다. 이 명령 안에서 `npm run build`를 실행한 뒤 Windows 의존성과 공식 SHA-256을 확인한 Node 실행 파일을 포함한 검증용 ZIP을 만들었다. 검증용 ZIP은 게시·배포하지 않았다.

| 확인 | 결과 |
|---|---|
| ZIP 최상위와 `program` 안내 | 모두 존재, 바이트 동일 |
| 최종 PC 설치 안내 원문과 TXT | UTF-8 BOM·CRLF 변환을 제외한 내용 동일 |
| 안내 manifest 항목 | `PC설치안내.txt`, 9,722바이트 |
| 안내 SHA-256 | `1a805d28b74801ea7fb1236671092e84abbe0e433f10070f217475998480ebdf` |
| ZIP 안의 안내·설치·업데이트 스크립트 | 최종 수정 소스와 일치 |
| 패키징된 안내 크기·해시 | 실제 PowerShell 검사 통과 |
| 패키징된 PowerShell 6개 파일 | 파싱 오류 없음 |

`install-guide.test.ps1`은 실제 설치·제거 스크립트를 실행한다. Windows 전용 OS 검사·특수 폴더·WScript COM·레지스트리·robocopy·대화상자·서버 종료 경계만 가상화하고 manifest 검증·파일 교체·등록·복구 흐름은 제품 코드를 사용한다.

검사한 5개 시나리오: 새 설치의 파일·바로가기, 안내가 없는 이전 버전에서 업데이트, 제거, 첫 설치 실패 후 새 바로가기 제거, 기존 설치 실패 후 이전 바로가기 바이트·프로그램 복원. 업데이트 검사에서는 기동 실패 시 기존 안내 바로가기 유무 두 경우를 확인했다. 설명서 테스트는 루트·하위 경로에서 시작 메뉴 안내 두 곳, ZIP 안내, 7장, 내부 앵커와 그림 13개를 확인한다.

## 부가 검사에서 발견한 기존 ZIP 문제

패키징 폴더 전체를 PowerShell의 `Assert-ProgramPayload`로 검사하는 추가 시도는 `app/node_modules/.bin/crc32`에서 실패했다. macOS의 `npm ci`가 만든 심볼릭 링크는 길이가 23바이트지만 manifest는 링크가 가리키는 파일의 3,919바이트를 기록한다. 해당 링크·대상·manifest 값은 기존 게시 0.5.11 ZIP에도 동일하게 존재한다.

이 전체 payload 검사를 통과한 것으로 집계하지 않았다. 이번에 추가한 안내 TXT의 크기·해시는 PowerShell에서 별도로 통과했다. 기존 링크 처리 문제는 요청 범위인 안내 파일·바로가기 외의 패키징 동작이어서 수정하지 않았다. 실제 Windows에서 ZIP을 풀었을 때의 링크 처리와 설치 결과는 미확인이다.

## 보존 범위와 미확인

버전·기존 EXE·게시 릴리즈·공식 규칙·서명·운영 자료·`output/`은 보존했다. 원본 배포 파일의 해시를 변경하지 않았으며 push·릴리즈 게시·EXE 빌드는 하지 않았다.

Windows 10/11 실기기 설치, 실제 WScript COM이 만든 `.lnk`와 시작 메뉴 표시·클릭, 메모장 실행, Windows PowerShell 5.1 실행은 **미확인**이다. 이번 PowerShell 실행 환경은 macOS의 7.6.9이다. 설치 EXE의 실제 실행도 **미확인**이다.

이미 설치되어 실행 중인 과거 버전의 업데이트 도우미는 소급 변경되지 않는다. 새 설치 프로그램을 통한 정상 업데이트는 안내 파일·바로가기를 추가하지만, 과거 도우미가 실행한 업데이트의 최종 기동 실패 복구까지 이번 코드 보강이 소급 보장하지는 않는다.

증거는 로컬 전용 `data/install-guide-file-2026-11-02/`에 보관한다. `packaging-verification.json`, `guide-powershell-verification.json`, `shortcuts-final/install-guide-results.json`, `desktop-maintenance/verification.json`, `existing-symlink-check-failure.json`과 각 명령의 로그를 포함한다.
