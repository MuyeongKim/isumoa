# 이수모아 0.4.0 — 처음 사용자 관점 10회 검증·EXE 결과

작성: 2026-10-28 (KST)

**10회 UI 시나리오 검증을 완료하고 발견한 제품 오류·불편 8개를 보완했다. Windows x64용 EXE 설치 파일을 생성하고 압축·내부 파일·해시·배포 구성 검증을 마쳤다. Windows 실제 설치·실행은 미검증이다.**

## 검증 방식과 범위

각 회차에 별도 DB·가상 관리자·가상 직원 2명을 만들고 실제 브라우저 화면의 파일 선택·버튼·체크박스·다운로드를 조작했다. 첫 설정부터 명단 → 교육 기준 → 수료증 업로드 → 검수 → 현황 → 실제 XLSX·개인별 PDF ZIP 다운로드까지 수행했다. API로 자료를 넣거나 생성한 출력을 UI 통과로 대신하지 않았다. 실제 초보 사용자 10명이 참여한 사용성 시험은 아니다.

원본 업무 데이터와 분리한 ::1의 가상 환경만 변경했다. 자동 테스트와 DB·파일 검사는 UI 작업 후 결과를 추가 확인하는 용도다. 실제 첨부 수료증은 이번 가상 시험이나 배포물에 넣지 않았다.

회차별 원본 증거는 [STATE.json](../data/release-validation-2026-10-27/STATE.json) 및 rounds/R01~R10/evidence/의 AX 기록·화면·실제 받은 파일·verification.json에 있다. 각 회차에서 정상 수료증 2건을 확정했고, 내려받은 개인별 PDF는 직원당 정확히 1쪽이었다. 합계 20개 PDF와 10개 현황 XLSX, 기관 제출 양식 1개를 검사했다. 원본 파일 24개의 저장 해시를 확인했다. 기본 청렴교육에 대한 2명 이수를 확인한 것으로, 다른 법정교육까지 전부 이수한 것으로 판단하지 않았다.

## 자동 검증

- 타입 검사 통과: npm run typecheck
- 29개 테스트 파일, 287개 테스트 통과. 양식 빈 줄 보존 회귀 사례 포함.
- 최종 화면 빌드와 git diff --check 통과.
- 백업 UI 완료 후 별도 restore --check에서 SHA-256·SQLite 무결성·감사/접속 로그 체인·원본/쪽 이미지 존재 확인. 실제 운영 DB를 과거 백업으로 바꾸지 않았다.

## Windows 배포 파일

- 파일: 이수모아-설치-0.4.0-win-x64.exe
- 크기: 112.5 MiB (117,923,749 bytes)
- SHA-256: cf172002b748978667320abefab05e49af5ddc02860fdcb1eeaa547806c2419c
- NSIS 3.13 Unicode 설치 화면·바탕화면/시작 메뉴 실행 아이콘. 별도 Node 설치 없이 실행하도록 Node 24.14.0, Windows x64 OCR 라이브러리와 한국어 모델 포함.
- 설치용 EXE와 실행기 스텁은 x86 PE이며 Windows x64에서 64비트 Node·OCR을 호출한다. Node와 네이티브 라이브러리 9개는 x64 PE임을 확인했다.
- 7zz 압축 무결성 통과. 추출한 제품 파일 12,165개 전부를 빌드 원본 해시와 대조했다. NSIS 기본 보조 파일 3개는 별도 확인했다. 최종 web/dist 561개 파일 해시도 일치했다.
- 운영 DB·개인 수료증·업로드·백업·설정·알려진 로그인값 미포함 확인. 기존 설치 자료는 별도 사용자 데이터 폴더에 두며, 설치기가 덮어쓰지 않는 구성이다.
- 코드 서명 없음. 기관 PC의 보안 정책 허용 여부와 Windows 10·11 실제 설치/실행/업그레이드/제거, Windows에서의 실제 OCR 기동은 확인하지 못했다. 따라서 이 결과를 Windows 현장 인수 완료로 해석하면 안 된다.

## 사용 중인 앱 반영

현재 사용 중인 127.0.0.1:31735를 0.4.0으로 다시 실행했다. 먼저 DB 사본을 보관하고, 변경 전후 업무 테이블 해시가 같음을 확인했다. 확정 17건·제외 9건은 유지됐다. 사용자 탭은 이동·새로고침하지 않았다. 별도 3000/5173 개발 실행은 설정 임시파일 경로가 없어 재시작하지 않고 그대로 유지했다.
