# 이수모아 운영 가이드

설치를 마친 뒤 교육 담당 관리자가 하는 일입니다. 설치·HTTPS·서비스 등록·복원 절차는 **설치가이드.md**를 보세요.

## 1. 한 해의 흐름

| 때 | 하는 일 | 화면 |
|---|---|---|
| 연초 | 인사 명단 반영(전보·신규·퇴직), 교육 과정 기준 확인, 서무 계정·담당 부서 정리 | 직원 명단, 교육 과정, 설정 > 사용자 계정 |
| 수시 | 서무가 이수증을 올리고 검수·확정 | 이수증 올리기, 검수함 |
| 분기·반기 | 부서별 미이수자 독려 | 대시보드, 이수 현황, 내보내기(미이수자 시트) |
| 연말 | 현황 엑셀·증빙 ZIP·교육별 합본 PDF로 결과 보고 | 내보내기 |
| 다음 해 | 보관기간이 지난 연도 파기 | 설정 > 백업·보관 |

### 제출 양식에 채워 받기

상급기관·부서에 내는 엑셀 양식이 따로 있으면 **내보내기 > 양식 올리기·관리**에서 빈 양식(.xlsx)을 한 번 올려 두세요.

1. 양식을 올리면 머리글 줄, 사람을 쓸 빈 줄, 합계·서명란을 찾아 색으로 보여 줍니다. 틀리면 줄 번호를 고치고 "이 줄 번호로 다시 읽기"를 누릅니다.
2. 열마다 넣을 내용(성명·부서·직급, 교육별 이수 표시·이수일·이수 시간 등)을 확인합니다. 미리보기에 앞의 몇 명이 채워진 모습이 나옵니다.
3. 이름과 쓰는 부서를 정해 저장하면, 내보내기의 "제출 양식에 채우기"에서 연도·부서를 골라 받습니다. 전체 부서는 부서별 파일(ZIP)로 나눠 받을 수도 있습니다.

받은 파일은 엑셀로 열어 한 번 훑어보고 내 주세요. 양식에 그림·글상자가 있거나 다른 시트를 가리키는 수식이 있으면 저장할 때 주의 표시가 나옵니다.

## 2. 정기 점검표

| 주기 | 점검 | 어디서 |
|---|---|---|
| 매일 (자동) | 백업, 보관기간 지난 접속기록·감사 로그 정리 | 서버가 스스로 — 결과는 설정 > 백업·보관 |
| 매주 | "고칠 점"이 없는지 (HTTPS, 디스크 공간, 백업 실패) | 설정 > 시스템 점검 |
| **매월** | **접속기록 점검**: 사용자별 요청·내려받기·야간·주말 접속·로그인 실패, 내려받은 사유가 적절한지 → "점검 완료로 기록" | 설정 > 접속기록 > 월 점검 |
| 매월 | 기록 위·변조 확인 ("지금 확인"이 모두 정상인지) | 설정 > 접속기록 |
| 분기 | 복원 연습: `restore --check`가 "복원할 수 있습니다"인지 | 서버에서 restore.bat / restore.sh |
| 매년 | 보관기간이 지난 연도 파기, 쓰지 않는 계정 끄기, 서무 담당 부서 다시 확인 | 설정 > 백업·보관, 설정 > 사용자 계정 |

월 점검에서 이상한 점(예: 업무 시간 밖의 대량 내려받기, 반복된 로그인 실패)이 보이면 해당 사용자에게 확인하고, 점검 메모에 결과를 남깁니다. 메모는 감사 로그에 기록됩니다.

## 3. 무엇이 기록되나

- **감사 로그** (설정 > 감사 로그, 기본 3년 보관, 최소 3년): 로그인·로그아웃·로그인 실패, 계정·권한·부서 변경, 명단 반영, 이수증 확정·제외, 내려받기(사유 포함), 설정 변경, 백업, 파기, 접속기록 점검.
- **접속기록** (설정 > 접속기록, 기본 2년 보관, 최소 2년): 로그인한 사용자의 모든 요청 — 누가, 언제, 어느 IP에서, 어떤 주소(검색 조건 포함)를 조회·변경·내려받았는지. 화면이 몇 초마다 자동으로 묻는 요청과 목록용 작은 이미지는 빼고 남깁니다.
- 두 기록 모두 앞 기록과 이어지는 고유값(해시)을 함께 저장해, DB에서 고치거나 지우면 "기록 위·변조 확인"에서 드러납니다. 보관기간이 지나 앞부분이 정리된 것은 정상으로 봅니다.

## 4. 개인정보 다루기

- **내려받기 사유**: 엑셀·ZIP·합본 PDF를 받을 때 사유를 고르게 되어 있습니다. 받은 파일은 목적에 쓰고 나면 지워 주세요.
- **주민등록번호**: 저장하지 않습니다. 명단에 있어도 생년월일만 남기고, 이수증 글자(PDF 글자·OCR 결과)에 있으면 뒷자리를 가려 저장합니다(`850312-1******`). 다만 **쪽 이미지에는 원본 그대로 보이므로**, 주민번호가 찍힌 이수증은 가능하면 가리고 내도록 안내하세요.
- **외부 전송 없음**: 이수증은 서버 안의 OCR로만 읽고, AI 서버나 인터넷으로 보내지 않습니다.
- **계정**: 계정을 함께 쓰지 않습니다. 서무가 바뀌면 옛 계정을 끄고(사용 안 함) 새 계정을 만듭니다. 퇴직·전보로 담당 부서가 바뀌면 바로 고칩니다.

## 5. 개인정보 안전성 확보조치와 이 시스템

기관의 보안성 검토 때 참고할 수 있도록 정리했습니다. 기준과 보관기간은 기관 지침·법령으로 최종 확인하세요.

| 항목 | 이 시스템에서 |
|---|---|
| 접근 권한 관리 | 관리자·서무 역할, 서무는 담당 부서 직원·이수증만 (서버에서 매 요청 확인). 계정·권한 변경 이력을 감사 로그에 3년 이상 보관 |
| 접근 통제 | 로그인 5회 실패 시 10분 잠금, 60분 미사용 자동 로그아웃, 로그인 최대 12시간, HTTPS(4장), 다른 사이트에서 보낸 요청 차단 |
| 비밀번호 | 영문 대·소문자·숫자·특수문자 중 2종류 이상이면 10자 이상, 3종류 이상이면 8자 이상. 복원할 수 없는 방식(scrypt)으로 저장, 처음 로그인·초기화 뒤 바꾸게 함 |
| 접속기록 | 2년 이상 보관, 월 1회 점검 화면, 내려받기 사유, 위·변조 확인 |
| 암호화 | 전송 구간 HTTPS. 고유식별정보(주민번호)는 저장하지 않음 |
| 파기 | 보관기간이 지난 연도를 확인 후 파기(되돌릴 수 없음), 파기 내역은 감사 로그(파기 대장). 백업에서도 보관 개수가 지나면 사라짐 |
| 백업 | 매일 자동 백업(다른 디스크 권장), 무결성 검사, 복원 연습 |

## 6. 보관기간과 파기

**설정 > 백업·보관**에서 정합니다.

| 자료 | 기본 | 최소 | 지우는 방법 |
|---|---|---|---|
| 이수증 자료(원본·쪽 이미지·이수 기록) | 5년 | 1년 | 관리자가 연도를 확인하고 파기 |
| 접속기록 | 2년 | 2년 | 서버가 매일 자동 정리 |
| 감사 로그 | 3년 | 3년 | 서버가 매일 자동 정리 |
| DB 백업본 | 30개 | 3개 | 백업할 때 오래된 것부터 정리 |

이수증 자료의 보관기간은 다음 해 1월 1일부터 셉니다(5년이면 2021년 자료는 2027년부터 파기 대상). 파기하면 그해 묶음의 원본 파일·쪽 이미지·이수 기록·대상 제외가 지워지고, 그해까지 퇴직한 사람 중 다른 해 기록이 없는 직원 정보도 함께 지웁니다. 필요하면 먼저 내보내기에서 현황 엑셀을 받아 기록물로 남기세요.

## 7. 시범 서버: 단일 사용자 모드

> **시범 서버에서만 쓰고, 반드시 nginx 로그인으로 막은 뒤에 켭니다.** 운영 서버에는 켜지 않습니다.

앱 안의 로그인 화면 없이 nginx 로그인(basic auth) 하나로만 보호하는 시범용 모드입니다. 켜면 5장의 접근 통제(역할 구분·로그인 잠금·자동 로그아웃)가 **적용되지 않고**, nginx 로그인을 통과한 사람은 모두 관리자입니다.

| 켜면 | |
|---|---|
| 들어가는 방법 | 로그인 화면 없이 바로 들어갑니다. 세션이 없는 요청은 **사용 중인 관리자 가운데 가장 먼저 만든 계정**으로 처리합니다. 관리자가 아직 없으면 처음 설정 화면이 나오고, 만든 뒤부터 자동으로 들어갑니다 |
| 화면 | 로그아웃·비밀번호 변경 단추가 없습니다. 서버도 비밀번호 변경을 거부하고, "비밀번호를 먼저 변경" 요구는 건너뜁니다 |
| 그대로인 것 | 데이터를 바꾸는 요청이 우리 화면에서 온 것인지 확인하는 장치(다른 사이트가 보낸 요청 차단)는 그대로입니다. 브라우저는 nginx 로그인 정보를 다른 사이트의 요청에도 붙여 보내므로 이 장치가 꼭 필요합니다. 처음 설정 화면은 관리자가 이미 있으면 열리지 않습니다 |
| 점검 화면 | 설정 > 시스템 점검의 "고칠 점"에 단일 사용자 모드 경고가 계속 나옵니다 (정상) |

### 켜는 순서

1. **nginx에 로그인을 먼저 겁니다.** 아이디·비밀번호 없이는 어떤 주소도 열리지 않는지 확인한 뒤 다음으로 넘어갑니다.

   ```nginx
   server {
     # listen·server_name·인증서(ssl_certificate)는 기관 환경대로
     auth_basic           "이수모아 시범";
     auth_basic_user_file /etc/nginx/isumoa.htpasswd;   # htpasswd로 만든 파일

     client_max_body_size 32m;                          # 이수증 올리기(파일당 30MB)
     location / {
       proxy_pass http://127.0.0.1:8080;                # config.json의 port
       proxy_set_header Host $host;
       proxy_set_header X-Forwarded-For $remote_addr;
       proxy_set_header X-Forwarded-Proto $scheme;
     }
   }
   ```

2. `config.json`에 아래를 넣고 서버(서비스)를 다시 시작합니다. nginx가 HTTPS를 맡으면 설치가이드 4장 "나)"처럼 `trustProxy`·`cookieSecure`도 함께 켭니다.

   ```json
   "host": "127.0.0.1",
   "singleUser": true
   ```

3. 로그인 창(nginx)만 거치고 바로 들어가지는지, 그리고 nginx를 거치지 않은 주소(서버 IP:포트)로는 접속되지 않는지 확인합니다.

**안전장치**: `host`가 `127.0.0.1`·`localhost`·`::1`이 아니면(예: `0.0.0.0`) 서버가 오류를 내고 시작하지 않습니다. `singleUser`에 `true`·`false`가 아닌 값(따옴표 친 `"true"` 등)을 써도 시작하지 않습니다. 끄려면 `singleUser`를 지우거나 `false`로 바꾸고 다시 시작하면 평소 로그인으로 돌아갑니다.

### 알아 둘 점

- **같은 서버 안의 다른 프로그램·계정**은 nginx를 거치지 않고 `127.0.0.1:포트`로 직접 접속해 관리자가 될 수 있습니다. 여러 사람이 로그인해 쓰는 공용 서버에서는 켜지 않습니다.
- **누가 했는지**: 감사 로그·접속기록에는 모든 사용자가 같은 관리자 계정으로 남습니다. 사람을 가리려면 nginx 로그인 계정을 사람마다 따로 만들고, nginx의 접속 로그(사용자 이름)로 확인합니다.
- 서무의 담당 부서 제한도 없습니다(모두 관리자). 부서별 권한을 시험하려면 이 모드를 끄고 확인합니다.
- 이 모드에서는 관리자 비밀번호를 바꿀 수 없습니다. 운영으로 옮기기 전에는 모드를 끄고 로그인해, 관리자 비밀번호를 바꾸고 서무 계정을 만듭니다.
