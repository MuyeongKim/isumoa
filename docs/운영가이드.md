# 운영 가이드

설치를 마친 뒤 교육 담당 관리자가 하는 일입니다. 설치·HTTPS·서비스 등록·복원 절차는 **설치가이드.md**를 보세요.

## 1. 한 해의 흐름

| 때 | 하는 일 | 화면 |
|---|---|---|
| 연초 | 인사 명단 반영(전보·신규·퇴직), 교육 과정 기준 확인, 서무 계정·담당 부서 정리 | 직원 명단, 교육 과정, 설정 > 사용자 계정 |
| 수시 | 서무가 이수증을 올리고 검수·확정 | 이수증 올리기, 검수함 |
| 분기·반기 | 부서별 미이수자 독려 | 대시보드, 이수 현황, 내보내기(미이수자 시트) |
| 연말 | 현황 엑셀·증빙 ZIP·교육별 합본 PDF로 결과 보고 | 내보내기 |
| 다음 해 | 보관기간이 지난 연도 파기 | 설정 > 백업·보관 |

## 2. 정기 점검표

| 주기 | 점검 | 어디서 |
|---|---|---|
| 매일 (자동) | 백업, 보관기간 지난 접속기록·감사 로그 정리 | 서버가 스스로 — 결과는 설정 > 백업·보관 |
| 매주 | "고칠 점"이 없는지 (HTTPS, 디스크 공간, 백업 실패) | 설정 > 시스템 점검 |
| **매월** | **접속기록 점검**: 사용자별 요청·내려받기·야간·주말 접속·로그인 실패, 내려받은 사유가 적절한지 → "점검 완료로 기록" | 설정 > 접속기록 > 월 점검 |
| 매월 | 기록 위·변조 확인 ("지금 확인"이 모두 정상인지) | 설정 > 접속기록 |
| 분기 | 복원 연습: `restore --check`가 "복원할 수 있습니다"인지 | 서버에서 restore.bat / restore.sh |
| 매년 | 보관기간이 지난 연도 파기, 쓰지 않는 계정 끄기, 서무 담당 부서 다시 확인 | 설정 > 백업·보관, 설정 > 사용자 계정 |

월 점검에서 이상한 점(예: 업무 시간 밖의 대량 내려받기, 반복된 로그인 실패)이 보이면 해당 사용자에게 확인하고, 점검 메모에 결과를 남깁니다. 메모는 감사 로그에 기록됩니다.

## 3. 무엇이 기록되나

- **감사 로그** (설정 > 감사 로그, 기본 3년 보관, 최소 3년): 로그인·로그아웃·로그인 실패, 계정·권한·부서 변경, 명단 반영, 이수증 확정·제외, 내려받기(사유 포함), 설정 변경, 백업, 파기, 접속기록 점검.
- **접속기록** (설정 > 접속기록, 기본 2년 보관, 최소 2년): 로그인한 사용자의 모든 요청 — 누가, 언제, 어느 IP에서, 어떤 주소(검색 조건 포함)를 조회·변경·내려받았는지. 화면이 몇 초마다 자동으로 묻는 요청과 목록용 작은 이미지는 빼고 남깁니다.
- 두 기록 모두 앞 기록과 이어지는 고유값(해시)을 함께 저장해, DB에서 고치거나 지우면 "기록 위·변조 확인"에서 드러납니다. 보관기간이 지나 앞부분이 정리된 것은 정상으로 봅니다.

## 4. 개인정보 다루기

- **내려받기 사유**: 엑셀·ZIP·합본 PDF를 받을 때 사유를 고르게 되어 있습니다. 받은 파일은 목적에 쓰고 나면 지워 주세요.
- **주민등록번호**: 저장하지 않습니다. 명단에 있어도 생년월일만 남기고, 이수증 글자(PDF 글자·OCR 결과)에 있으면 뒷자리를 가려 저장합니다(`850312-1******`). 다만 **쪽 이미지에는 원본 그대로 보이므로**, 주민번호가 찍힌 이수증은 가능하면 가리고 내도록 안내하세요.
- **외부 전송 없음**: 이수증은 서버 안의 OCR로만 읽고, AI 서버나 인터넷으로 보내지 않습니다.
- **계정**: 계정을 함께 쓰지 않습니다. 서무가 바뀌면 옛 계정을 끄고(사용 안 함) 새 계정을 만듭니다. 퇴직·전보로 담당 부서가 바뀌면 바로 고칩니다.

## 5. 개인정보 안전성 확보조치와 이 시스템

기관의 보안성 검토 때 참고할 수 있도록 정리했습니다. 기준과 보관기간은 기관 지침·법령으로 최종 확인하세요.

| 항목 | 이 시스템에서 |
|---|---|
| 접근 권한 관리 | 관리자·서무 역할, 서무는 담당 부서 직원·이수증만 (서버에서 매 요청 확인). 계정·권한 변경 이력을 감사 로그에 3년 이상 보관 |
| 접근 통제 | 로그인 5회 실패 시 10분 잠금, 60분 미사용 자동 로그아웃, 로그인 최대 12시간, HTTPS(4장), 다른 사이트에서 보낸 요청 차단 |
| 비밀번호 | 영문 대·소문자·숫자·특수문자 중 2종류 이상이면 10자 이상, 3종류 이상이면 8자 이상. 복원할 수 없는 방식(scrypt)으로 저장, 처음 로그인·초기화 뒤 바꾸게 함 |
| 접속기록 | 2년 이상 보관, 월 1회 점검 화면, 내려받기 사유, 위·변조 확인 |
| 암호화 | 전송 구간 HTTPS. 고유식별정보(주민번호)는 저장하지 않음 |
| 파기 | 보관기간이 지난 연도를 확인 후 파기(되돌릴 수 없음), 파기 내역은 감사 로그(파기 대장). 백업에서도 보관 개수가 지나면 사라짐 |
| 백업 | 매일 자동 백업(다른 디스크 권장), 무결성 검사, 복원 연습 |

## 6. 보관기간과 파기

**설정 > 백업·보관**에서 정합니다.

| 자료 | 기본 | 최소 | 지우는 방법 |
|---|---|---|---|
| 이수증 자료(원본·쪽 이미지·이수 기록) | 5년 | 1년 | 관리자가 연도를 확인하고 파기 |
| 접속기록 | 2년 | 2년 | 서버가 매일 자동 정리 |
| 감사 로그 | 3년 | 3년 | 서버가 매일 자동 정리 |
| DB 백업본 | 30개 | 3개 | 백업할 때 오래된 것부터 정리 |

이수증 자료의 보관기간은 다음 해 1월 1일부터 셉니다(5년이면 2021년 자료는 2027년부터 파기 대상). 파기하면 그해 묶음의 원본 파일·쪽 이미지·이수 기록·대상 제외가 지워지고, 그해까지 퇴직한 사람 중 다른 해 기록이 없는 직원 정보도 함께 지웁니다. 필요하면 먼저 내보내기에서 현황 엑셀을 받아 기록물로 남기세요.
