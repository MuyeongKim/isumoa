# 이수모아 — 개발·배포 담당자 안내

일반 사용자는 [README의 Windows 설치 EXE](../README.md#windows-설치-파일-받기)를 이용합니다. 이 문서는 소스 수정·검사·설치본 생성과 저장소 관리를 담당하는 사람을 위한 안내입니다.

## 개발 환경

Node.js 24를 사용합니다. 실행 환경 버전은 저장소의 `.node-version`을 참고하세요.

```bash
npm install
npm run dev
```

개발 화면은 `http://localhost:5173`, API는 `http://localhost:3000`입니다. 처음 열면 기관명과 관리자 계정을 설정합니다.

| 명령 | 용도 |
|---|---|
| `npm test` | 단위·API 테스트 |
| `npm run typecheck` | 서버와 화면 타입 검사 |
| `npm run build` | 배포용 화면과 사용설명서 빌드 |
| `npm run samples` | 가상 직원 명단 생성 |
| `npm run samples:certs` | 가상 수료증과 정답 생성 |
| `npm run samples:forms` | 가상 제출 양식 생성 |
| `npm run eval -- --truth samples/certs/정답.json` | 판독 정확도 점검 |
| `npm run restore -- --check` | 백업 검사. 실제 복원 절차는 운영 가이드 참고 |

Windows 유지보수 검사는 `npm run verify:desktop -- --powershell pwsh --output data/desktop-check`로 실행합니다. `--program`으로 EXE 추출 폴더를 지정할 수 있습니다. 다른 OS의 PowerShell에서 하는 모의 검사와 Windows 실기기 설치·실행 검증은 구분해서 기록합니다.

## Windows EXE 만들기

빌드 PC에 NSIS가 필요합니다.

```bash
npm run release -- --target win-x64 --desktop --exe --download-node
```

`release/`에 EXE·ZIP 설치판이 생성됩니다. 실행용 Node.js, Windows용 OCR 엔진·모델과 글꼴을 함께 넣으므로 사용자가 실행 환경을 따로 설치하지 않습니다. 코드 서명과 Windows 실기기 검증 여부는 해당 릴리스에 명시합니다.

서버 설치본은 `npm run release`로 만듭니다. 다른 OS 대상은 `--target`과 `--download-node`를 사용하고 [서버 설치 가이드](설치가이드.md)의 환경 조건을 확인하세요.

## 저장소와 배포 원칙

1. GitHub와 GitLab의 `main`에는 같은 소스와 **같은 README**를 반영합니다. 일반 사용자 README는 제품 설명·Windows EXE 다운로드·설치·사용 순서를 먼저 안내합니다.
2. **배포 파일은 GitHub Releases에만 올립니다.** GitLab Releases나 저장소 파일 목록에 EXE·ZIP을 중복 업로드하지 않습니다.
3. 제품 코드가 바뀐 릴리스는 버전·소스 커밋·GitHub 태그를 맞춥니다. 문서 정리만 할 때 기존 배포 태그를 옮기거나 설치 파일을 덮어쓰지 않습니다.
4. 릴리스에는 Windows EXE, 선택 가능한 ZIP 설치판, 설치 안내, 검증 요약과 SHA-256을 제공합니다. 미검증 범위와 서명 여부를 함께 기록합니다.
5. 새 릴리스의 실제 파일 이름과 버전으로 README의 EXE·ZIP·검증 요약 링크를 갱신합니다. 최신 릴리스 링크는 계속 `https://github.com/MuyeongKim/isumoa/releases/latest`를 사용합니다.
6. 업로드한 파일을 다시 내려받아 해시를 대조하고 최신 릴리스 여부를 확인합니다. 두 저장소의 `main` 커밋과 README 내용도 확인합니다.

`data/`, `backups/`, `logs/`, `samples/`, `release/`와 로컬 개발 도구 설정은 소스 저장소에 올리지 않습니다. 실제 직원 명단·수료증·DB·계정 정보도 업로드하지 않습니다. 테스트에는 가상 또는 개인정보를 치환한 자료만 사용합니다.

개발환경 경로·임시 증거를 담은 내부 작업보고서와 다시 생성할 수 있는 홍보 HTML·배너·미리보기 GIF는 로컬에서 관리합니다. 사용자에게 필요한 검증 요약은 GitHub 릴리스에서 제공합니다.

## 주요 폴더

| 폴더 | 내용 |
|---|---|
| `web/` | 화면, PDF 쪽 처리와 프로그램 내 사용설명서 |
| `server/` | API, SQLite DB, OCR·판독·검수·집계, 백업·복원 |
| `shared/` | 화면과 서버가 함께 쓰는 타입·규칙 |
| `scripts/` | 샘플·평가, 설치본·문서 그림·로고 생성 |
| `deploy/` | Windows PC 설치·실행·업데이트·제거와 서버 서비스 스크립트 |
| `vendor/` | 설치본과 오프라인 OCR에 필요한 모델·고지 |
| `tests/` | 단위·API·Windows 유지보수 회귀 검사 |
| `docs/` | 사용자·설치·운영 안내와 필요한 화면 그림 |

원본과 읽은 값을 대조한 뒤 확정한 수료증이 이수 현황·출력의 근거가 됩니다. 공식 교육 목록에서 확인한 과정별 학습시간은 기관의 연간 의무 기준을 바꾸는 근거로 쓰지 않습니다.

## 그림·로고·소개 영상

- `npm run brand`: 로고 좌표, 브라우저 아이콘, Windows 아이콘과 문서용 로고를 생성합니다. [로고 사용 안내](brand/README.md)
- `npm run media:screens`: 사용설명서 화면 그림을 생성합니다.
- `npm run media:promo`: 소개 영상과 홍보용 출력물을 생성합니다. ffmpeg·글꼴 서브셋 도구 등 필요한 도구는 스크립트 주석을 참고하세요.

소개 영상의 편집용 원본은 `scripts/media/promo/promo.html`에 있으며 렌더링한 `docs/promo/promo.html`은 소스와 중복되는 생성물입니다. 현재 사용설명서에서 참조하는 화면 그림과 배포에 필요한 아이콘은 유지합니다.
