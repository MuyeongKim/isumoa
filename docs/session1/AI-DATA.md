# AI와 자료 처리 설명

## 실제 처리 과정

PDF 글자층 확인 → 글자가 부족하거나 손상된 경우 설치 PC의 AI-OCR → 항목 추출 규칙 → 직원 명단·교육 기준·공식 과정 목록 대조 → 중복·주제 충돌·시간·날짜 검사 → 담당자가 원본과 비교해 확정 → 현황·기관보고·증빙 출력.

| 구성 | 역할 | 한계 |
|---|---|---|
| kordoc 4.24.1 + 한국어 PP-OCRv5 ONNX | 이미지에서 글자 검출·인식. 설치 PC CPU에서 실행 | 기울기·화질·글꼴·배치에 따라 오독 가능 |
| tesseract.js + 로컬 한국어 학습 데이터 | 기본 OCR이 실행되지 않을 때 대체 | 기본 엔진과 결과가 다를 수 있어 원본 대조 필요 |
| TypeScript 규칙 | 성명·날짜·시간 등 항목 추출, 직원 대조, 교육 연결·충돌·중복 검사 | 새 서식·다의적인 과정명은 수동 검수가 필요 |
| 확정 과정 매핑 | 사용자가 확정한 과정명과 교육의 연결 저장 | 모델 파인튜닝이나 개인정보를 이용한 자동 재학습이 아님 |
| 담당자 | 잘못 읽은 값 수정, 인정 범위 판단, 최종 확정·제외 | 교육 충족 기준은 해당 기관 기준과 대조해야 함 |

이 프로그램의 실행 중 핵심 AI는 OCR입니다. 생성형 LLM이 수료 여부를 판단하거나 법적 인정을 결정하지 않습니다. 개발 보조 AI와 실행 중 OCR은 별도입니다. 기본·대체 OCR 두 개를 사용한다는 사실을 '2종 LLM 활용'으로 설명하지 않습니다. 대회 권장 항목과의 적합성은 실제 구성대로 설명하고 필요 시 주최 측에 확인합니다.

## 개인정보와 외부 통신

- 직원 명단·원본·이미지·읽은 글자·검수 결과는 설치 PC의 자료 폴더에 보관합니다. OCR 모델과 한국어 데이터는 설치본에 포함합니다.
- 사용자가 업데이트 확인·다운로드를 누를 때 GitHub에 버전·배포 파일을 요청합니다. 직원 명단·수료증·앱 로그인 쿠키를 요청에 담지 않습니다.
- DB·원본·백업은 앱 자체 암호화가 없습니다. Windows 계정·기관 디스크 암호화·폴더 접근권한으로 관리해야 합니다. 원본 이미지에는 개인정보가 남으므로 원본에 불필요한 번호는 가리고 수집합니다.
- 데스크톱 기본 접속은 PC 내부 주소입니다. 기관 서버로 공유하는 경우 인증·권한·TLS·네트워크 보안 검토가 별도로 필요합니다.
- 제출 자료에는 실존 직원 명단·수료증·운영 DB·백업·로그인 정보·사용자 경로를 넣지 않습니다. 가상 인물·가상 기관 자료를 별도로 생성합니다.

## 검증 수치의 의미

합성 표본 판독은 서식의 특정 조건을 반복 확인하는 검사입니다. 사용자가 제공한 자료로 규칙을 보완한 뒤 같은 자료를 다시 맞힌 결과는 회귀 검증으로 기록합니다. 새 합성 서식도 실제 신규 기관의 독립 표본과 같지 않습니다. 수작업 대비 시간 절감은 직원의 전체 작업 시간을 측정하기 전까지 주장하지 않습니다.

## 라이선스와 배포

kordoc은 MIT, PP-OCRv5 한국어 모델은 Apache-2.0으로 안내되며 모델 파일·해시·출처는 [모델 고지](../../vendor/ocr-models/NOTICE.md)에 기록되어 있습니다. tesseract.js 및 한국어 데이터, PDF.js, React, Node, ONNX Runtime, sharp, 글꼴 등의 라이선스 고지는 설치본 구성요소와 함께 보존합니다. 개발·빌드·런타임 의존성 목록은 배포 시 잠금 파일과 최종 패키지를 기준으로 검사합니다.

프로젝트 자체의 저작권 양도·공개 라이선스 부여·대회 동의·서명은 소유자의 결정 사항입니다. 이 문서는 이를 대신 동의하지 않습니다. EXE 코드 서명은 아직 없습니다.
