# 설치 가이드 (내부망 서버)

설치본 zip에는 프로그램과 실행용 Node.js가 모두 들어 있습니다. 인터넷 연결이나 별도 프로그램 설치가 필요 없습니다.
설치한 뒤의 일상 운영(백업 확인, 접속기록 점검, 파기 등)은 **운영가이드.md**를 보세요.

## 1. 서버 준비

- 운영체제: Windows Server 2016 이상, 또는 Linux(glibc 2.28 이상 — RHEL 8, Ubuntu 20.04 이상)
- 권장 사양: 2코어, 메모리 4GB, 데이터 디스크 20GB 이상 + **백업용 다른 디스크 또는 NAS**
- 방화벽: 접속 포트(기본 8080, HTTPS면 443 또는 8443)를 내부망에 엽니다.

## 2. 압축 풀기

경로에 한글과 공백이 없는 폴더에 풀어 주세요.

- Windows: `C:\edu-cert`
- Linux: `/opt/edu-cert` (서비스 계정을 만들어 주인으로 두기를 권합니다: `sudo useradd -r -s /usr/sbin/nologin educert && sudo chown -R educert /opt/edu-cert`)

```
edu-cert/
  app/                 프로그램 (업그레이드 때 이 폴더만 바꿉니다)
  node/                실행용 Node.js
  config.json          설정
  start.bat / start.sh       직접 실행 (창을 닫으면 꺼짐 — 시험용)
  service/             서비스 등록 (서버가 켜지면 저절로 실행)
  eval.bat / eval.sh         AI 인식 정확도 점검
  restore.bat / restore.sh   백업 복원·복원 연습
  data/                처음 실행하면 생깁니다 — DB와 이수증 파일
  backups/             백업 (config.json의 backupDir — 다른 디스크로 바꾸기를 권함)
  logs/                서버 로그 (날짜별, 90일 보관)
```

## 3. 설정 (`config.json`)

| 항목 | 기본값 | 설명 |
|---|---|---|
| `port` | 8080 | 접속 포트 |
| `host` | 0.0.0.0 | 모든 네트워크에서 접속 허용. 서버 안에서만 쓰려면 127.0.0.1 |
| `dataDir` | data | 데이터 폴더 (config.json 기준 상대 경로 또는 절대 경로) |
| `tls` | null | 이 서버가 직접 HTTPS를 맡을 때 인증서 (아래 4장) |
| `cookieSecure` | false | 리버스 프록시가 HTTPS를 맡을 때 true. `tls`를 쓰면 저절로 켜집니다 |
| `trustProxy` | false | 리버스 프록시 뒤에서 운영하면 true (실제 접속 IP를 기록하려고) |
| `sessionIdleMinutes` | 60 | 이 시간 동안 사용하지 않으면 자동 로그아웃 |
| `sessionMaxHours` | 12 | 로그인 후 최대 유지 시간 |
| `backupDir` | backups | 백업 폴더. **데이터와 다른 디스크나 NAS**로 바꾸세요 (예: `D:\\edu-cert-backup`, `/mnt/backup/edu-cert`) |
| `backupHour` | 2 | 매일 자동 백업 시각 (한국 시각, 0~23) |
| `logDir` | logs | 서버 로그 폴더. 서비스로 실행할 때 필요합니다 |
| `allowExternalAi` | true | false면 기관 밖(인터넷) AI 서버를 화면에서 고를 수 없습니다. 개인정보를 기관 밖으로 보내지 않는 것이 지침이면 false로 두세요 |

설정을 바꾸면 서버(서비스)를 다시 시작해야 반영됩니다.

## 4. HTTPS

로그인 비밀번호와 이수증 개인정보가 오가므로 내부망이라도 HTTPS를 권합니다. 두 방법 중 하나를 고르세요.

**가) 이 서버가 직접 HTTPS** — 기관에서 받은 인증서 파일을 `edu-cert/cert/`에 두고:

```json
"port": 443,
"tls": { "certFile": "cert/server.crt", "keyFile": "cert/server.key" }
```

- `certFile`은 PEM 형식으로, 중간 인증서가 있으면 서버 인증서 뒤에 이어 붙입니다.
- PFX(.pfx/.p12) 파일 하나만 있으면 `"tls": { "pfxFile": "cert/server.pfx", "passphrase": "암호" }`.
- 켜면 쿠키 Secure 표시와 HSTS(브라우저가 계속 HTTPS로만 접속)가 저절로 적용됩니다.
- 인증서 파일을 읽지 못하면 서버가 시작하지 않습니다(몰래 HTTP로 뜨지 않게). 로그에서 이유를 확인하세요.

**나) 리버스 프록시(웹서버·L4)가 HTTPS** — 기관에 이미 있는 웹서버가 HTTPS를 받아 이 서버(`http://127.0.0.1:8080`)로 넘기는 경우:

```json
"host": "127.0.0.1",
"trustProxy": true,
"cookieSecure": true
```

설정을 마치면 **설정 > 시스템 점검**에서 "고칠 점"이 없는지 확인합니다.

## 5. 처음 실행

먼저 `start.bat`(Windows) 또는 `./start.sh`(Linux)로 실행해 봅니다. 직원 PC 브라우저에서 `http(s)://서버주소:포트`로 접속하면 기관명과 관리자 계정을 만드는 화면이 나옵니다. 잘 되면 창을 닫고(또는 Ctrl+C) 6장대로 서비스로 등록합니다.

## 6. 서비스 등록 (서버가 켜지면 저절로 실행)

**Windows** — `service\install-service.bat`을 **관리자 권한으로 실행**합니다.

- Windows 작업 스케줄러에 `EduCertPlatform` 작업을 등록합니다(따로 받을 프로그램 없음). 서버가 켜지면 SYSTEM 계정으로 시작하고, 멈추면 1분 뒤 다시 시작합니다.
- 상태 확인: 작업 스케줄러 > 작업 스케줄러 라이브러리 > `EduCertPlatform`
- 멈추기·다시 시작: 작업 스케줄러에서 "끝내기"·"실행", 또는 PowerShell `Stop-ScheduledTask EduCertPlatform` / `Start-ScheduledTask EduCertPlatform`
- 등록 지우기: `service\uninstall-service.bat` (관리자 권한)

**Linux** — `sudo ./service/install-service.sh`

- systemd 서비스 `edu-cert`를 만들고 바로 시작합니다. 설치 폴더 주인 계정으로 실행합니다(`RUN_USER=계정 sudo -E ./service/install-service.sh`로 바꿀 수 있음).
- 443 같은 1024 아래 포트도 root 없이 씁니다.
- 상태: `systemctl status edu-cert` · 로그: `journalctl -u edu-cert` 또는 `logs/`
- 멈추기·다시 시작: `sudo systemctl stop edu-cert` / `sudo systemctl restart edu-cert`
- 등록 지우기: `sudo ./service/uninstall-service.sh`

**관리자 권한이 없는 곳 (개인 할당 공간, 컨테이너 등)** — `./service/run-background.sh`

- 백그라운드로 실행하고, 서버가 멈추면 5초 뒤 다시 켭니다. 터미널을 닫아도 계속 돕니다.
- 상태: `./service/run-background.sh status` · 끄기: `./service/run-background.sh stop` · 로그: `logs/`
- 컴퓨터(컨테이너)가 다시 켜질 때 자동으로 켜려면 `crontab -e`에 `@reboot /설치폴더/service/run-background.sh` 한 줄을 넣습니다(cron을 쓸 수 있는 경우).
- 개인 공간은 시범 운영에 쓰고, 정식 운영은 IT 승인을 받은 서버로 옮기기를 권합니다(9장의 백업·복원으로 옮김).

## 7. AI 연결

관리자로 로그인해 **설정 > AI 연결**에서 정합니다. 처음에는 꺼져 있고, 꺼져 있으면 규칙으로만 읽습니다.

1. **연결할 AI**를 고릅니다.
   - **기관 AI 서버**: 정보화 담당에게 받은 주소(예: `http://ai-server:8000/v1`, `/v1`까지), 모델 이름, API 키(있으면)를 넣습니다.
   - **Claude API**: 인터넷이 되는 서버에서만 됩니다. API 키를 넣고 "외부 AI로 이수증을 보내는 것을 허용합니다"를 켜야 저장됩니다. 이수증의 개인정보가 기관 밖으로 나가므로 기관 지침을 먼저 확인하세요.
2. **연결 테스트**를 누릅니다. 가상 이수증만 보내서 다음을 확인합니다.
   - 답 형식: JSON 스키마 강제 → JSON 모드 → 지시문만 순서로 시험해 되는 방식을 고릅니다.
   - 이미지 읽기: 스캔본 이미지를 AI가 직접 읽을 수 있는지. 안 되면 스캔본은 OCR 글자를 AI에 보냅니다.
   - 걸린 시간: 한 쪽을 읽는 데 걸린 시간.
   - "생각 과정(thinking)이 섞여 옵니다"라고 나오면 **추가 파라미터**로 꺼 주세요. vLLM+Qwen: `{"chat_template_kwargs": {"enable_thinking": false}}`, Ollama: `{"reasoning_effort": "none"}`.
3. **AI로 이수증 읽기**를 켜고 **저장**합니다. 이후에 올리는 이수증부터 AI로 읽습니다. 이미 올린 묶음은 이수증 올리기 화면의 "다시 읽기"로 다시 읽을 수 있습니다 (확정·제외한 이수증은 그대로 둡니다).

- **동시 처리 수**: AI 서버가 요청을 여러 개 함께 받을 수 있으면 2~4로 늘리면 빨라집니다.
- AI 서버가 멈추면 10초·1분 뒤에 다시 시도하고, 그래도 안 되면 규칙으로 읽어 두고 화면 위쪽에 알립니다. AI가 정상이 되면 "다시 읽기"로 다시 읽으면 됩니다.
- AI가 읽은 값과 규칙으로 읽은 값이 다르거나, 과정명으로 정한 교육과 AI가 고른 교육이 다르면 검수함에 주황색 "확인할 점"이 붙습니다. 확인할 점이 없는 이수증은 검수함의 **정상 n건 일괄 확정**으로 한 번에 확정할 수 있습니다.
- 우리 시험(가상 스캔본 40쪽)에서는 스캔 이미지를 직접 읽는 모델이 OCR 글자만 받는 모델보다 확실히 정확했습니다. 기관 AI 서버가 이미지 입력을 지원하는지가 모델 크기보다 중요합니다.

## 8. AI 정확도 점검

서무가 이수증을 어느 정도 확정한 뒤, 확정 결과를 정답으로 삼아 AI가 얼마나 맞게 읽는지 확인할 수 있습니다. 이수증 내용은 바꾸지 않습니다.

```
eval.bat --truth confirmed                (Windows)
./eval.sh --truth confirmed               (Linux)
./eval.sh --truth confirmed --rules       AI 없이 규칙으로만 읽었을 때와 비교
./eval.sh --truth confirmed --model 다른모델 --vision off   다른 모델로 시험
./eval.sh --truth confirmed --batch 3 --limit 20            묶음 3의 앞 20쪽만
```

결과의 **표시 없이 틀림**이 가장 중요합니다. 확인할 점 없이 '정상'으로 분류됐는데 틀린 쪽의 비율로, 1% 미만이어야 일괄 확정을 믿고 쓸 수 있습니다.

## 9. 백업과 복원

**자동 백업** — 매일 `backupHour`시(기본 2시)에 `backupDir`에 만듭니다. 그 시각에 서버가 꺼져 있었으면 켜진 뒤 그날 안에 합니다.

```
backups/
  db/app-20261023-020000.db   DB 사본 (보관 개수: 설정 > 백업·보관, 기본 30개)
  db/app-20261023-020000.json 체크섬·무결성 검사 결과
  files/  pages/              원본 파일·쪽 이미지 (바뀐 것만 복사, 파기한 것은 지움)
```

- **설정 > 백업·보관**에서 마지막 백업 결과를 보고 "지금 백업"을 누를 수 있습니다.
- DB 사본은 서버를 멈추지 않고 만들며, 만들 때마다 SQLite 무결성 검사를 합니다.
- 백업 폴더를 통째로 테이프·외부 저장장치에 한 번 더 옮겨 두면(기관 백업 정책) 더 안전합니다.

**복원 연습** (분기마다 권장) — 백업본이 실제로 되살릴 수 있는 상태인지 검사만 합니다. 지금 데이터는 바뀌지 않으며, 서버를 멈출 필요도 없습니다.

```
restore.bat --check            (Windows, 가장 최근 백업)
./restore.sh --check           (Linux)
./restore.sh --list            백업 목록
./restore.sh --check app-20261020-020000.db
```

체크섬, DB 무결성, 감사 로그·접속기록 이어짐, 원본 파일이 백업 폴더에 다 있는지 확인하고 "이 백업으로 복원할 수 있습니다"를 보여 줍니다.

**실제 복원** — 서버가 망가졌거나 데이터를 되돌려야 할 때:

1. 서비스를 멈춥니다 (6장).
2. `restore.bat --apply --yes` 또는 `./restore.sh --apply --yes` (특정 백업은 파일 이름을 함께)
   - 먼저 검사(--check와 같은 내용)를 하고, 통과한 백업만 복원합니다.
   - 지금 DB는 `data/restore-before-날짜/`로 옮겨 두고, 백업 DB와 원본 파일·쪽 이미지를 `data/`로 되살립니다.
   - 서버가 켜져 있으면 복원하지 않습니다.
3. 서비스를 다시 시작하고 화면에서 확인합니다.

**새 서버로 옮길 때** — 새 서버에 설치본을 풀고 `config.json`의 `backupDir`을 옛 백업 폴더(복사본)로 맞춘 뒤 `--apply --yes`로 복원합니다.

## 10. 업그레이드

1. 서비스를 멈춥니다.
2. 새 설치본의 `app/` 폴더로 기존 `app/` 폴더를 바꿉니다. (`data/`, `backups/`, `config.json`, `cert/`는 그대로 둡니다.) 새 설치본의 `service/`, `*.bat`, `*.sh`도 바꿔 두면 좋습니다.
3. 서비스를 다시 시작합니다. DB 구조가 바뀌는 경우 `data/backups/`에 자동으로 사본을 만든 뒤 바꿉니다.

## 11. 디스크 사용량

올린 이수증의 원본 파일(`data/files/`)과 쪽 이미지(`data/pages/`)가 쌓입니다. 쪽마다 약 0.2~0.5MB이므로 직원 500명이 한 해 8장씩 내면 2~4GB 정도이고, 백업 폴더도 비슷한 크기가 듭니다. 보관기간이 지난 연도는 **설정 > 백업·보관**에서 파기해 공간을 돌려받습니다.

## 12. 문제가 생겼을 때

| 증상 | 확인할 곳 |
|---|---|
| 접속이 안 됨 | 서비스 상태(6장), `logs/server-날짜.log`, 방화벽 포트 |
| 서버가 바로 꺼짐 | 로그의 마지막 오류. 흔한 원인: 포트를 다른 프로그램이 씀, 인증서 파일 경로가 틀림, 데이터 폴더 권한 |
| 계정이 잠김 | 로그인 5번 틀리면 10분 잠김. 관리자가 **설정 > 사용자 계정 > 비밀번호 초기화**로 바로 풀 수 있습니다 |
| 화면 위쪽에 AI 장애 안내 | **설정 > AI 연결 > 연결 테스트**로 원인 확인. 그동안은 규칙으로 읽습니다 |
| 백업 실패 | **설정 > 백업·보관**의 오류 내용, 백업 폴더 권한·남은 공간 |
