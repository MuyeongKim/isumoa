# 이수모아 0.4.1 — 설치 실패 복구·실행 서버 식별 보완

검증일: 2026-10-28 (KST)

요청한 두 가지를 구현하고, 실패 재현 검증과 EXE 생성·추출본 검사를 마쳤다. Windows 실제 설치 UI·실행 환경 검증은 별도이며 아직 하지 못했다.

## 1. 업데이트 실패 복구

- 새 파일을 기존 프로그램과 같은 디스크의 별도 폴더에 준비하고 모든 파일의 SHA-256·크기·개수를 확인한 뒤 디렉터리를 교체한다. 복사·파일 검증 단계가 실패하면 기존 프로그램은 종료하거나 변경하지 않는다.
- 교체 직전에 기존 이수모아의 안전한 종료를 확인한다. 종료 확인에 실패하면 설치를 중단하고 강제로 프로세스를 죽이지 않는다.
- 폴더 교체 후 바로가기·앱 등록에서 실패해도 이전 프로그램 파일과 저장해 둔 등록 상태로 되돌린다. 이전 제품 자료를 새 위치로 옮긴 경우에는 자료 위치도 되돌리는 처리를 포함했다.
- 파일 잠금 등으로 복구 자체가 막히면 복구 자료를 지우지 않고 위치를 안내한다. OS 강제 종료·전원 차단 도중의 복구까지 검증한 것은 아니다.
- 설치·실행·제거는 하나의 프로세스 간 잠금을 공유한다. 설치 완료 후 자동 실행 전에 잠금을 해제해 새 실행을 막지 않도록 했다.

## 2. 이수모아 서버인지 확인

- PC 실행본은 제품 식별자와, 매번 새로 만든 난수에 대한 HMAC 응답을 제공한다. 설치된 사용자 데이터 폴더의 실행 열쇠로 검증된 응답만 승인한다. 확인 요청에는 실행 열쇠 자체를 보내지 않는다.
- 일반 HTTP 200, 제품명만 흉내 낸 JSON, 잘못된 서명, 다른 데이터 폴더의 열쇠, HTML, 리디렉션, 과도한 응답을 승인하지 않는다. 확인되지 않은 프로그램이 포트를 쓰면 브라우저를 열지 않고 안내한다.
- 0.4.0 이하 실행본은 확인 프로토콜이 없으므로 포트를 소유한 PID와 설치 폴더의 node.exe 실행 경로가 일치할 때만 종료 요청을 허용한다. 이전 제품의 별도 포트 설정도 읽는다.

## 실제 수행한 재검증

**PowerShell 유지보수 시나리오 24건 + 서로 다른 프로세스의 잠금 시나리오 3건 통과. 단위/API 테스트 290건(30개 파일), 타입 검사, 빌드, git diff --check 통과.**

검증은 가상 파일·가상 설정과 메모리 DB에서 수행했다. 테스트한 유지보수 함수는 최종 EXE에서 추출한 실제 스크립트이며, HTTP 확인에는 제품의 실제 Fastify API를 사용했다. 실행 환경은 macOS arm64의 PowerShell 7.6.9였다. Windows에 없는 macOS 시험에서는 파일 복사 수단만 Copy-Item으로 대체하고, 폴더 교체·해시·복구 함수는 실제 제품 코드를 실행했다. 레지스트리·바로가기 등록 실패는 콜백과 가상 등록 파일로 재현했다.

EXE 추출본 전체 파일을 설치용 manifest 함수로 검사하는 과정에서 숨김 파일 속성 처리를 보완했고, 숨김 파일을 포함한 회귀 시험과 최종 전체 파일 검사를 다시 통과했다.

## 최종 EXE

- 파일: 이수모아-설치-0.4.1-win-x64.exe
- 크기: 118,353,898 bytes (약 112.9 MiB)
- SHA-256: 969fdc577cb5514d1782baeaa7c71a1647124b0430dff04b387057c4e6fc14f1
- 압축 무결성 검사 통과. 추출한 제품/설치 파일 12,167개 해시가 빌드 원본과 일치했다. 설치 manifest에 나열된 12,165개 파일을 실제 PowerShell 함수로 모두 검사했다.
- 서버·공통 소스·Windows 스크립트 90개가 현재 소스와 일치함을 추가 확인했다. Node·네이티브 OCR 라이브러리는 Windows x64 PE이며 한국어 모델이 포함됐다. 운영 DB·원본 수료증·개인 로그인값은 포함하지 않았다.
- 설치 파일과 실행기는 x86 NSIS 스텁이며 Windows x64의 Node·OCR을 호출한다. 코드 서명은 없다.

Windows 10·11에서의 NSIS 설치 UI, Windows PowerShell 5.1 실행, robocopy, CIM/포트 조회, 실제 레지스트리·바로가기, 업그레이드·제거·OCR 전체 기동은 이 Mac에서 확인하지 못했다. 위 검증을 Windows 현장 인수 완료로 해석하면 안 된다.
