# 이수모아 0.4.3 — 부서 시범운용 새 20회 검증·고도화 결과

2026-10-28 (한국 시각). 기준 버전 0.4.2에서 새로 20회를 실행했다. 앞선 10회 결과를 이번 회차로 재사용하지 않았다.

**20회 실제 화면 검증 완료. 오류 10개를 수정하고 관련 동작을 재검증했다. 자동 테스트 307개와 설치·유지보수 모의 검사 38건을 통과했다. 새 0.4.3 EXE를 생성했다. Windows 실기기 설치·실행은 미검증이며 코드 서명은 없다.**

사진 OCR의 증서번호 한 글자 누락은 확인된 한계로 남아 있다. 9회차의 2건은 검수를 다시 열어 원본과 대조하고 수동으로 정정했다. 자동 인식 100% 또는 현장 검증 완료라는 의미가 아니다.

## 검증 방법과 범위

매 회차 별도 DB·관리자·가상 직원과 실제 파일을 준비하고, 처음 설정 → 명단 등록 → 교육 기준 확인 → 수료증 업로드 → 검수 → 현황 → 실제 XLSX·개인별 PDF ZIP 다운로드를 수행했다. CUA로 파일 선택·버튼·체크박스·입력을 조작했다. API를 호출해 자료를 넣은 결과를 UI 통과로 세지 않았다. 이번 20회는 가상 자료를 이용한 시나리오 검사이며 20명의 실제 초보자가 참여한 사용성 시험은 아니다.

문제는 전후 화면 또는 실제 다운로드·DB 검사로 기록했다. 통신 실패와 지연은 검증 탭에만 주입하고 해제했다. 운영 DB에서 조작 시험을 하지 않았고, 화면 빌드도 별도 web-dist로 분리했다. 마지막 20회차는 0.4.3의 새 환경에서 수행했다.

직원·교육 편집 창에는 닫기 확인, 저장 중 닫기 방지, 브라우저 뒤로가기·이동 보호를 적용했다. 저장이 실패하면 입력을 유지한다. 다른 직원 창을 열 때는 이전 직원의 오류와 편집 상태를 분리한다. 교육 횟수는 정수로 검증하고 시간 기준의 소수 입력은 유지한다. 문서 가져오기에서는 창 닫기·파일 교체·직접 입력에서 가져오기로 전환할 때 값을 보호한다.

일괄 제외의 동시 수정 충돌은 전체 처리를 거부하고, 중단 사유를 화면에 남긴다. 제외 기록 일부가 있는 상태에서 대기를 초기화한 경우에도 결과가 없는 원본 쪽 수와 다시 읽기 경로를 안내한다.

파일명에서는 확장자가 붙은 CON.txt 등의 Windows 예약 이름과 유니코드·조합 파일명의 길이를 처리했다. 예약 이름은 확장자가 붙어도 사용할 수 없다는 [Microsoft의 파일명 규칙](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file)에 맞췄다. 실제 ZIP 안의 2개 파일이 서로 덮어쓰지 않고 255바이트 이하 이름을 갖는지 확인했다.

## 백업·복원 검증

수정 전에는 원본 누락·같은 크기 손상, 쪽 이미지 누락·손상 등 4종 모두가 ‘복원 가능’으로 잘못 판정됐다. 수정 후 같은 사례는 모두 실패 종료(1)하고, 정상 사본만 성공 종료(0)했다. 새 백업은 원본·쪽 이미지·미리보기의 SHA-256을 기록하며 원본은 DB의 기존 해시와도 대조한다.

백업 전에 원본 저장소를 검사해 누락·손상된 상태가 기존 정상 백업을 잘못 정리하지 않도록 했다. 같은 크기로 손상된 백업 사본도 다음 백업에서 다시 복사한다. 같은 초에 여러 번 백업해도 고유 이름을 사용한다. 실제 UI에서 연속 3회 성공과 손상 사본 1개의 재복사를 확인했다.

19회차에는 기존 0.4.2 복원 스크립트가 IPv6 포트 실행 중에도 DB 교체를 허용하는 것을 격리된 대상과 TCP 서버로 재현했다. 새 스크립트는 이를 거부하고 기존 DB를 보존했다. 이후 서버를 종료하고 별도 위치에 실제 복원했으며, 같은 크기의 손상 원본도 정상 파일로 회복했다. 복원 DB의 파일 해시가 백업 DB와 같았고, 복원한 앱에서 직원 2명·확정 2건·개인별 PDF·기관 양식의 2시간 값과 합계 위치까지 실제 UI로 확인했다.

실제 복원은 자료 복사와 DB 사본 준비를 먼저 마친 뒤 DB를 교체하고 원래 DB를 복구용 폴더에 남긴다. 운영 DB를 과거 사본으로 되돌리지는 않았다.

이전 백업의 쪽 이미지에는 체크섬 기록이 없을 수 있다. 이 경우 원본 해시와 쪽 존재를 검사하고 체크섬이 없는 범위를 안내한다. 파기로 원본이 이미 제거된 과거 사본은 완전 복원이 불가능할 수 있다. 백업 폴더의 db·files·pages를 함께 보관해야 한다.
