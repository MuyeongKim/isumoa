# 검수함 사용성 개선 및 검증 (2026-11-01)

기준: v0.5.10 / `2380b34`. 운영 데이터와 분리한 개발 검증이다. 새 배포판의 Windows 실기기 검증 결과를 뜻하지 않는다.

## 반영 내용

1. **4대 폭력 통합교육 연결**: 과정명에 네 주제가 모두 있거나 `4대폭력`, `4대 폭력예방`, `통합 폭력예방(4대)`처럼 전체 범위가 명시되면 통합교육 1개로 연결한다. 2~3개 주제, 일부·제외·택1 표현, 본문에만 나열된 주제는 확인 표시를 유지한다. 사용자 규칙의 확인 표시와 기존 공식 과정명 연결도 유지한다.
2. **기존 검수 대기 경고 재평가**: 현재 과정명과 인정 교육이 정확히 맞는 대기의 `training-name-suggestion`만 읽을 때 재평가한다. 저장된 notes·인정 연결·수정값은 쓰지 않는다. 중복·시간·직원·주제 충돌 등 다른 경고는 유지하며, 확정·제외 기록은 변경하지 않는다.
3. **이수증 아닌 쪽 한 번에 제외**: 현재 검색 결과의 대기 자료 중 `not-certificate` 표시가 있는 쪽을 확인창에서 제외한다. 원본은 보존하고 사유는 `이수증 아님`으로 기록한다. 검수 대기로 복원할 수 있다. 서버는 미리보기와 적용 모두에서 권한·대기 상태·판독 상태·현재 경고를 재검사한다. 토큰은 사용자·모드·원본 상태·인정 연결에 묶인다. 기존 체크 선택 제외 동작은 유지한다. 500건을 넘으면 검색 범위를 좁히도록 안내한다.
4. **이수 현황 가로 안내**: 요약 표와 직원별 표 각각 오른쪽에 남은 열이 있으면 안내와 그림자를 표시한다. 스크롤 끝에서는 사라지며 화면 크기와 표 크기가 바뀌면 다시 판단한다. 기존 성명 고정, 요약, 검색·부서·연도·미이수 필터와 집계 범위는 유지한다.
5. **개발용 평가 일치**: 샘플 정답 32건을 `violence-integrated`로 통일하고 생성기도 같은 코드를 사용한다. 평가 스크립트는 설치된 공식·사용자 규칙과 항목 별칭을 사용한다. 참고시간 경고도 포함한다. 정답 유출 방지를 위해 확정 이력의 학습 매핑은 사용하지 않는다.

공식 `defaultRules.json`의 내용·버전과 서명 fixture는 변경하지 않았다. 기존 서명 검증·미리보기의 버전 비교 흐름을 유지한다. 샘플 정답 JSON은 저장소에 포함하고, 다시 생성할 수 있는 PDF·사진은 기존처럼 제외한다.

## 자동 검증

- `npm run typecheck`: 통과
- `npm test`: 51개 파일, 550개 테스트 통과 (기존 522개 + 이번 28개)
- `npm run security:check`: 통과. 운영 의존성 취약점 0개, 보안 회귀 43개 통과
- `npm run build`: 통과

제한 없는 병렬 실행에서는 기존 백업·47개 과정·엑셀 테스트 일부가 5초 제한시간에 걸렸다. `maxWorkers: 2`로 동시 실행 수를 제한해 기본 `npm test` 전체를 재실행했다. 제한시간과 검증 조건은 늘리거나 완화하지 않았다.
- `npm run eval -- --truth samples/certs/정답.json`: 분리 DB의 50쪽 평가. 직원·이수일·교육·시간 각각 48/48, 이수증 아님 표시 2/2, 모두 맞은 쪽 50/50, 표시 없이 틀림 0쪽

새 단위·API 테스트는 명확한 제목의 표기 변형, 부분·제외 표현, 과거 대기 경고, 공식 과정 보존, 본문 오인 방지, 적용 연도·비활성 교육, 평가 규칙, 스크롤 경계, 제외 대상·권한·감사·복원·상태 변경·모드 토큰을 확인한다.

## 실제 UI 검증

검증 주소는 별도 서버 `http://[::1]:47970`이다. 실제 운영 계정·DB 대신 가상 관리자와 새 DB를 사용했다. 브라우저 크기는 1366×800으로 설정하고 종료 시 원래대로 복원했다. 기존 사용자 탭은 변경하지 않았다.

1. 새 기관과 가상 관리자 설정 후 `samples/직원명단_2026.xlsx`를 UI로 올려 120명·8부서를 등록했다. 오류 0명.
2. `스캔묶음_재무과.pdf` 40쪽과 개별 폭력예방 5개·장애인식개선 5개를 올렸다. 합계 11개 파일·50쪽, 업로드 실패 0개. 실제 로컬 kordoc OCR과 PDF 글자층을 사용했다.
3. 폭력예방으로 검색하면 20건만 보이고 모두 정상 일괄 확정 대상이 됐다. 20건을 실제 확정했다.
4. 검색 초기화 후 이수증 아닌 2쪽만 확인창에서 제외했다. 미저장 값이 있으면 버튼이 비활성화됨을 확인했다. 사유와 감사 로그, 다른 자료 보존을 확인했다.
5. 나머지 정상 28건을 확정해 확정 48건·제외 2건·대기 0건이 됐다.
6. 1366×800에서 요약 표(1428px)와 직원 표(1371px)가 표시 영역(1022px)을 넘고 양쪽 표에 가로 안내가 표시됐다. 직원 표를 오른쪽 끝(349px)으로 옮기면 해당 안내가 사라지고 성명 열은 고정됐다.
7. 내보내기에서 사유를 고른 뒤 16시트 명단 엑셀을 실제 내려받았다. ExcelJS 읽기, ZIP CRC, 모든 XML·rels 구문을 통과했다. 브라우저 다운로드 이벤트 대기는 시간 초과였지만 실제 Downloads 파일과 내용을 별도로 확인했다.
8. 같은 파일 및 이름만 바꾼 동일 바이트 파일을 다시 올리면 둘 다 중복으로 건너뛰었다. 같은 수료증을 PDF로 재저장해 다른 바이트로 올린 1건은 검수 대기에 남고 `duplicate-confirmed`로 수동 확정도 차단됐다. 확정 48건은 그대로였다.

평가 스크립트는 UI 업로드 때 생성한 OCR 캐시를 다시 사용했다. 별도의 OCR 속도 재측정이나 자동 확정의 일반 정확도 수치로 해석하지 않는다. 추가 중복 사례를 포함한 검증 DB 최종 상태는 확정 48건·제외 2건·대기 1건이다.
